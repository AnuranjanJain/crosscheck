# Architecture decisions

Crosscheck processes PDFs locally. It stores the document content hash, page-level evidence, recovered table rows and bounding boxes, extracted facts, relationships, and failures in SQLite. Facts contain their original source wording and a small extensible attributes object. Relationships always point to two facts, which in turn point to evidence. SQLite foreign-key enforcement prevents facts or evidence from becoming orphaned.

The baseline parser recognizes numerical claims, simple semantic statements, common reporting periods, and reporting scope. It performs unit normalization for crore, lakh, and billion when the source specifies those units. Each fact receives an inspectable metric key. The comparison engine requires metric identity, then checks period, scope, unit, and estimate status before labeling a discrepancy. It uses decimal arithmetic and source precision to distinguish a rounded corroboration from a conflicting value. Different contexts are reported as contextual reconciliation, not an error.

Adding a document compares its new facts with existing knowledge. Unrelated relationships remain intact; `scripts/reconcile.py` performs an explicit full rebuild after comparison-rule changes. Ollama is optional; semantic embeddings are not implemented. Model quotes must match page evidence, which does not guarantee correct interpretation.

Processing configuration is stored separately from document identity. Results replace an existing document only inside one transaction after successful extraction and comparison. Run events are stored separately for failure inspection. A single UI session invokes model requests sequentially; concurrent processing and automatic page-level resume are not implemented.

Period tables use recovered headers and cells; header-only tables can recover strictly aligned numerical text rows. Attributed date tables compare explicitly named reporting columns while excluding broader metrics. These rules are generic heuristics, not a guarantee of semantic equivalence. Exact source coordinates and headers remain inspectable. The acceptance manifest is consumed only by the reporting script, never by extraction or comparison.
